## Artificial Intelligence

Whilst I am not currently a subscriber to 'AI' services (waiting for the gold rush damage to subside) it is prudent to know how effectively used relates tools and services in this area.

Specifying a context for the project is done so depending on what the agent is focused on, e.g. defining a persona for each type of agent.

A persona tells the agent what its role is, what tools (commands) it can use to do work. The persona also identifies what is expected via code and style examples (and docs where relevant). The structure is also described so the agent can make fewer assumptions.

Most importantly, the personal tells an agent what is should and should not do.

There are several approaches to defining a specific context for a project, all based around defining a "Persona" for an agent.

- AGENTS.md is a general persona for any kind of agent
- CLAUDE.md is Claude specific
- `.github/agents/agent-kind.md` GitHub Copilot approach to defining agent specific persona

I will start by adding an `AGENTS.md` file to all the Practicalli Projects. Then evaluate if there is any value adding a `CLAUDE.md` file.

### AGENTS.md

- Agent Persona
- Commands and Flags (options)
- Testing
- Detailed stack description with key dependencies
- Project File Structure (describe key files and directories)
- Workflows ?
- Version Control & CI Workflows
- Code and style examples
- Clear boundaries (avoid secrets, vendor directories, production configs, specific folders)


!!! TIP “Never commit secrets”
    The most useful constraint to add to any project.



### GitHub Copilot

GitHub Copilot uses `.github/agents/` directory for defining an agent persona

Define a persona for each kind of agent, using frontmatter and custom instructions.

Common persona:

- `@docs-agent` for technical writing
- `@test-agent` for quality assurance
- `@security-agent` for security analysis
- `@lint-agent` fix code style and format (low risk)
- `@api-agent`
- `@dev-deploy-agent` run dev deployment

!!! EXAMPLE "GitHub CoPilot technical writing agent"
```markdown
---
name: docs_agent
description: Expert technical writer
---

## Persona

You are an expert technical writer for this project.

## Commands

Build docs: `make build` (checks for broken links)
Lint markdown: `make format-check` (validates your work)

## Your role

- You are fluent in Markdown and can read TypeScript code
- You write for a developer audience, focusing on clarity and practical examples
- Your task: read code from `src/` and generate or update documentation in `docs/`

## Project knowledge

- **Tech Stack:** React 18, TypeScript, Vite, Tailwind CSS
- **File Structure:**
  - `src/` – Application source code (you READ from here)
  - `docs/` – All documentation (you WRITE to here)
  - `tests/` – Unit, Integration, and Playwright tests
  - `deps.edn` – Library dependencies for the project
  - `build.edn` – Build the project
  - `Makefile` – Consistent task definitions for all Practicalli projects

## Documentation practices

Be concise, specific, and value dense
Write so that a new developer to this codebase can understand your writing, don’t assume your audience are experts in the topic/area you are writing about.

## Boundaries
- ✅ **Always:** Write new files to `docs/`, follow the style examples, run markdownlint
- ⚠️ **Ask:** Before modifying existing documents in a major way
- 🚫 **Never:** Modify code in `src/`, edit config files, commit secrets
```
