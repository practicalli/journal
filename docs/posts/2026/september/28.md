I had [a quick test of the Clojure CLI REPL](#practicalli) on a simple Practicalli project, comparing the experience with my current preference of Rebel Readine.

Clojure CLI has an interesting [Inspector feature](#inspector) and the ability to evaluate part of an expression. A config file should be added to define key mappings for these features (no key mappings by default, but there is an example config and docs to help).

There is a lot more to the config example that I didnt use, so lots more to explore there.

I hope the project [simplifies the paths for the config file](#startup) (reduce the verbosity), to make working with the project more accessible. It does honour the Clojure CLI config location, which is excellent. It may be a longer path due to the amount of configuration that is possible.

There is a lot of promise to the Clojure CLI REPL, but for my workflow (and without tab completion of namespace and function names) its not ready to be a replacement for Rebel Readline (yet).

> NOTE: the auto-require was a configuration aspect I missed (although it seems strange that clojure.core isnt a default). I guess if this would be used for different Clojure implementations then that would make sense.

I will keep a lookout for updates to this project though and continue testing.

For day to day work I will continue [using Rebel Readline as my Terminal REPL prompt](https://practical.li/clojure/clojure-cli/repl/#rebel-terminal-repl-ui){target=_blank}

## Practicalli

I am trying out the [Clojure CLI REPL](https://github.com/clojure/clojure-cli.repl) is a new project to provide a rich command line REPL support, using Java Jline.

Features:
- multi-line editing
- bracket highlighting
- structural editing
- inline eval
- doc lookup for Clojure and Java
- a data inspector
- configurable prompts
- custom keybindings
- Vim or Emacs editing modes :sparkling_heart:

I've added aliases to [Practicalli Clojure CLI Config](https://practical.li/clojure/clojure-cli/practicalli-config/){target=_blank} using my standard naming convention:

- `:repl/cli` start nREPL server and rich REPL client
- `:repl/serve` start nREPL server only
- `:repl/attach` start a client and attach to an existing nREPL server

The nREPL server creates an `.nrepl.port` file containing the local port the nREPL server is listening too


### Startup

I have Java v25.0.4 installed and Clojure CLI 1.12.4.1602, running on Debian Linux.

Aliases to run the tool were added to the Clojure user level configuration `$XDG_CONFIG_HOME/clojure/deps.edn` using [Practicalli Clojure CLI Config](https://practical.li/clojure/clojure-cli/practicalli-config/){target=_blank}.

The `XDG_CONFIG_HOME` environment variable was checked that it still points to the correct location.

```shell-output
❯ echo $XDG_CONFIG_HOME
/home/practicalli/.config
```

Run the nREPL server and client using the Clojure CLI tool.

```
clojure -M:repl/cli
```

The command proceeds to download the internet (I regularly clear the local Maven cache so this took a few seconds).

The Clojure CLI REPL honours the Clojure CLI location. It did not try to create a separate `$HOME/.clojure` directory, which is good as I dont use that classic approach to dotfiles. I checked as the Clojure CLI REPL docs only mention `~/.clojure` as the config directory.

The CLojure CLI REPL did not create a config file, but did create a history buried deep in the path `$XDG_CONFIG_HOME/clojure/.cljconf/org.clojure/clojure-cli.repl/history`

Its unclear why the config and history files need to be on such a deep path when the could be easier to discover at:

- history: `$XDG_CONFIG_HOME/clojure/cli-repl/history`
- config: `$XDG_CONFIG_HOME/clojure/cli-repl/config.edn`
- dependencies: `$XDG_CONFIG_HOME/clojure/cli-repl/deps.edn`

Or perhaps even a shared history file with any Clojure CLI based REPL... although Rebel Readline creates a `.rebel-readline-history` in the root of each project.

- history: `$XDG_CONFIG_HOME/clojure/history`
- config: `$XDG_CONFIG_HOME/clojure/cli-repl-config.edn`
- dependencies: `$XDG_CONFIG_HOME/clojure/cli-repl-deps.edn`

> NOTE: it felt confusing to have a `.cljconf` dotfile within the parent Clojure CLI dotfile, especially when the Clojure CLI config is in `$HOME/.config/clojure/.cljconf`. I missed that `.cljconf` had been created at first glance.
>
> The `.cljconf` name could easily be mistaken for something related to Clojure CLI rather than Clojure CLI REPL.



### First use

I could evaluate expressions and multi-line typing worked.

```clojure
(map
 inc
 [1 2 3 4 5])
```

History of expressions is accessed via the Up arrow ++arrow-up++ or via `Ctrl r` and typing a pattern (just like the usual shell history search)

I did not get docs after pausing at the end of a function name. I didnt realise initially that [a configuration file with key mappings](#configuration-file) is required to make some features work.

Because the key mappings were not at hand, I didnt know how to do structural editing, editing a multi-line expression, call docs or inspect a result).

`Ctrl d` to exit the REPL prompt back to the shell prompt. I first evaluated `(quit)`, `(exit)`, `:quit`, `:exit` to see if they would exit the REPL, but without success.

Its a new project, so just a little bit of docs or hunting through the code should fix that challenge. I wonder if the Clojure CLI REPL project will be part of a demo at the Clojure Conj this week?

### Auto-require namespaces

To get `clojure.core` required in any other namespace but `user` the config needs to add and auto-require.

!!! EXAMPLE "Practicalli declarative config for Clojure CLI REPL (so far)"
    ```clojure
    ;; Practicalli Config for Clojure CLI REPL
    {:bracket-pairs false
     :eval-form-at-cursor "M-e"
     :doc-at-cursor "M-d"
     :inspect "M-i"

     :auto-require
     [[clojure.core :refer :all]
      [clojure.repl :refer [apropos demunge dir doc find-doc pst root-cause source]]]}
    ```

Now I can use all the functions in `clojure.core` unqualified in any namespace, along with my preferred functions from clojure.repl.
