## Zensical

Practicalli projects have all changed to a Zensical approach to documentation generation, for local builds and publishing via continuous integration.

All projects have migrated from "Material for MkDocs" to a Zensical workflow except for those websites that contain a blog.

The main [Practical.li](https://practical.li) hosts my blog and [Practicalli Journal](https://practical.li/journal) has several blog posts combined (Personal Journal, Clojurists Together reports, 100 days of code).

On the 22nd September Zensical [released the blog plugin in version 0.0.64](https://github.com/zensical/zensical/releases/tag/v0.0.64){target=_blank}.

On 24th Septermber Zensical [released the rss blog plugin in version 0.0.65](https://github.com/zensical/zensical/releases/tag/v0.0.65)


### Blog plugin

I tested the Practicalli Journal site after updating Zensical and adding the blog plugin to the `zensical.toml` configuration.

!!! NOTE "Add blog plugin to Zensical Config"
    ```toml title="zensical.toml"
    # ----------------------------------------------------------------------------
    # Blog
    # ----------------------------------------------------------------------------
    [project.plugins.blog]
    # ----------------------------------------------------------------------------
    ```

!!! NOTE "Add blog and RSS plugins to Zensical Config"
    ```toml title="zensical.toml"
    # ----------------------------------------------------------------------------
    # Blog
    # ----------------------------------------------------------------------------
    [project.plugins.blog]
    [project.plugins.rss]
    # ----------------------------------------------------------------------------
    ```


I updated the blog and rss configuration in `zensical.toml`

```toml
# ----------------------------------------------------------------------------
# Blog Support
# ----------------------------------------------------------------------------
# [project.plugins.meta]

[project.plugins.blog]
blog_dir = "."
post_url_format = "{date}/{slug}"
draft = false
draft_on_serve = true        # show drafts in local server (default true)
draft_if_future_date = true  # draft not published, but not marked as draft in local serve

# Only build with allowed categories
categories_allowed = [
    "100daysofcode",
    "clojure",
    "clojurists-together",
    "debian",
    "git",
    "github",
    "hardware",
    "hyprland",
    "journal",
    "megalinter",
    "neovim",
    "practicalli",
]

[project.plugins.rss]
image = "https://github.com/practicalli/graphic-design/blob/live/logos/practicalli-logo.png?raw=true"
match_path = "posts/.*"
length = 100                  # articles to include (Default 20)
date_from_meta = {as_creation = "{date}"}
categories = ["categories", "tags",]
# ----------------------------------------------------------------------------
```


The blog is still working correctly.

The RSS feed shows, but the posts are taking their respective timestamps from either the git commit timestamp or file system timestamp (if not in version control).

Each post in the RSS feed should be taking the date from the front matter `date` value.

I am assuming this is an issue with the RSS plugin, but do not know for sure. I started a [discord thread](https://discord.com/channels/1289187620659789824/1553461571261440010) to gain some feedback before spending more time creating a repeatable repo.


## Cycling

I have a Coospo cadence sensor to help me gauge effort whist riding and help manage endurance over longer distances (and to a small extent during hill climbing).

On a mid-week ride the sensor was not showing up on my cycle computer, but it was only a short ride.

I removed the sensor from the bike and revolving my hand holding the sensor I could see an alternating red and blue light.

An alternating Red & Blue light seems to indicate a low battery, although an Internet search didnt provide any conclusive answers.

I replaced the battery, a CR3032, and the Coospo sensor seems to be working again.

On my Strava Profile, the Coospo sensor was added to the Deadpool bike as a component (selecting a crank as there wasnt actually a bike sensor option).
